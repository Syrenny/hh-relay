# Поиск Python backend-вакансий

Готовить краткий персональный выпуск вакансий за последние 24 часа. Использовать только инструменты `search_vacancies` и `get_vacancy` сервера hh-relay; не обращаться к `api.hh.ru` и не подменять отсутствующие данные догадками.

## Профиль кандидата

Искать позиции Python backend уровня Junior/Junior+ или с опытом до трёх лет.

Считать положительными сигналами:

- Python как основной backend-язык;
- Django, Django REST Framework или FastAPI;
- PostgreSQL и содержательная работа с базами данных;
- продуктовая разработка;
- сложная бизнес-логика, интеграции, асинхронность или highload;
- удалённая работа либо локация Новосибирск/Москва.

Считать отрицательными сигналами:

- преимущественно frontend или fullstack с доминирующим frontend;
- парсинг сайтов как основная задача;
- Senior/Lead/Architect и требования существенно выше Junior+;
- обязательный опыт более трёх лет;
- роль, в которой Python не относится к основной работе.

## Сбор кандидатов

1. До поиска просмотреть предыдущие выпуски в истории этой периодической задачи и собрать уже показанные vacancy ID.
2. Выполнить `search_vacancies` минимум для следующих пар запроса и опыта:
   - `Python backend` + `noExperience`;
   - `Python backend` + `between1And3`;
   - `Django Python` + `between1And3`;
   - `FastAPI Python` + `between1And3`.
3. Сначала искать без `area`, чтобы не потерять удалённые позиции. Если ответ `truncated=true`, повторить соответствующий поиск отдельно для Новосибирска (`area=4`) и Москвы (`area=1`).
4. Объединить результаты по vacancy ID. Удалить явные нерелевантные позиции по названию до загрузки полных карточек.
5. Не показывать ID из предыдущих выпусков. Повторить вакансию только при материальном изменении зарплаты, формата, названия или требований; новое `published_at` само по себе изменением не считать.
6. Выбрать до 15 наиболее перспективных новых ID и вызвать `get_vacancy` для каждого. Оценивать требования и формат только по полной карточке.
7. Если история предыдущих выпусков недоступна, явно предупредить одной строкой, что гарантировать отсутствие повторов невозможно.

## Оценка

Назначать ровно одну оценку:

- **Сильное совпадение** — уровень реалистичен, Python backend является основой роли, есть несколько положительных сигналов и нет явного блокирующего требования.
- **Спорно** — вакансия потенциально подходит, но уровень, стек, формат или характер задач требуют уточнения.
- **Не стоит тратить время** — обнаружен явный отрицательный сигнал. Включать не более трёх таких вакансий и только когда по краткой карточке они выглядели правдоподобно; очевидный шум просто отбрасывать.

Не завышать оценку из-за одного совпавшего ключевого слова. Не считать отсутствие зарплаты отрицательным сигналом само по себе.

## Формат выпуска

Начать с заголовка `Вакансии Python backend за <дата>` и одной строки со статистикой: сколько уникальных вакансий просмотрено, сколько полных карточек изучено и был ли поиск усечён.

Сгруппировать вакансии по оценке в порядке:

1. Сильное совпадение.
2. Спорно.
3. Не стоит тратить время.

Для каждой вакансии указать:

- название и vacancy ID;
- компанию;
- зарплату или `не указана`;
- формат работы и город;
- 2–4 ключевых требования;
- точное время публикации и понятный относительный возраст;
- ссылку;
- оценку и краткое обоснование в 1–2 предложениях.

Не копировать полное HTML-описание. Убирать HTML-разметку при пересказе. Не повторять одинаковые требования в нескольких полях.

Если новых релевантных вакансий нет, сообщить об этом кратко и указать число просмотренных вакансий. Не заполнять выпуск нерелевантными позициями ради количества.
