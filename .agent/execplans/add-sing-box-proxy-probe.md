# Пробный запуск sing-box в Vercel

## Цель

Проверить, может ли Vercel Function запускать `sing-box`, подключаться через один VLESS + REALITY узел и получать обычную SSR-страницу hh.ru. До успешной проверки не переводить рабочие REST и MCP endpoints на прокси.

## Принятые решения

- Использовать один выбранный пользователем VLESS + REALITY узел без подписки, selector и ротации локаций.
- Не добавлять URI, UUID, Reality public key, short ID или полную конфигурацию в Git и логи.
- Передавать одну полную ссылку через защищённую Vercel Environment Variable `SINGBOX_VLESS_URL`; конфигурацию `sing-box` генерировать внутри приложения.
- Запускать `sing-box` без TUN-интерфейса: локальный SOCKS5 listener на `127.0.0.1` и VLESS outbound.
- Добавить отдельный диагностический endpoint; основной `/api/vacancies/search` пока продолжит работать напрямую.
- Не возвращать клиенту HTML hh.ru, cookies, конфигурацию proxy или другие чувствительные данные.

## Архитектура

```text
GET /api/proxy-health
        |
        v
SingBoxManager -> 127.0.0.1:19080 -> sing-box -> VLESS Reality -> hh.ru
        |
        v
httpx через socks5://127.0.0.1:19080
```

`SingBoxManager` должен:

- лениво запускать один процесс на serverless-инстанс;
- разбирать VLESS URL и создавать конфигурацию внутри `/tmp` с правами `0600`;
- запускать бинарник без shell;
- ограниченно ждать готовность локального порта;
- переиспользовать живой процесс на тёплых вызовах;
- не запускать несколько процессов при конкурентных запросах;
- собирать только ограниченный диагностический stderr без секретов;
- корректно сообщать об отсутствующей конфигурации, ошибке запуска и неготовом SOCKS-порту.

## Бинарник

- Использовать закреплённую версию официального Linux amd64 `sing-box`.
- Получать архив во время подготовки deployment или хранить бинарник способом, который гарантированно попадает в Vercel Function bundle.
- Проверять SHA-256 перед упаковкой.
- Не загружать и не исполнять неподтверждённый бинарник во время пользовательского HTTP-запроса.
- Точный способ упаковки выбрать после локального spike и проверки структуры Vercel Python bundle.

## Диагностический endpoint

`GET /api/proxy-health` выполняет один запрос через SOCKS5 к странице поиска hh.ru и возвращает только:

- `status`: `ok` или `error`;
- состояние процесса `sing-box`;
- HTTP status hh.ru;
- итоговый hostname после редиректов;
- время запроса;
- размер HTML;
- наличие `HH-Lux-InitialState`;
- стабильный код ошибки без внутренних секретов.

Endpoint не принимает произвольный URL, чтобы не превратиться в открытый proxy или SSRF-инструмент.

## Этапы

1. Выбрать закреплённую версию `sing-box`, проверить официальный архив и SHA-256.
2. Сделать локальный spike запуска процесса с тестовой конфигурацией без обращения к пользовательскому ключу.
3. Реализовать менеджер процесса и безопасную загрузку `SINGBOX_VLESS_URL`.
4. Добавить SOCKS-поддержку `httpx` и отдельный клиент для probe.
5. Добавить `/api/proxy-health` с минимальной типизированной моделью ответа.
6. Добавить unit-тесты конкурентного запуска, отсутствующей/повреждённой конфигурации, timeout и успешной проверки HTML.
7. Обновить README инструкцией настройки VLESS URL только в Vercel.
8. Запустить Ruff, pytest и `git diff --check`.
9. После deployment вызвать probe и изучить результат до переключения поиска на proxy.

## Критерии приёмки

- Секрет VLESS отсутствует в репозитории, ответах API и логах.
- На одном serverless-инстансе одновременно существует не более одного процесса `sing-box`.
- Probe не принимает URL или другие параметры назначения.
- Успешный probe подтверждает `200` и наличие `HH-Lux-InitialState`, а не только доступность TCP.
- Ошибки запуска и proxy имеют стабильные безопасные коды.
- Основные REST и MCP endpoints не меняют сетевой маршрут до отдельного решения пользователя.
- Ruff, тесты и `git diff --check` проходят.

## Риски

- Vercel может не включить бинарник в Function bundle или запретить его исполнение.
- Архитектура runtime может отличаться от выбранной сборки.
- Холодный старт процесса может не уложиться в доступный бюджет времени.
- Исходящий VLESS-сервер может быть доступен, но его IP может получить `403`, CAPTCHA или защитную страницу hh.ru.
- Файлы в `/tmp` и процесс не гарантированно сохраняются между invocations; реализация должна корректно восстанавливаться.

- 2026-08-26: `vercel.json` проверен по актуальной JSON Schema Vercel; Ruff, 32 теста и `git diff --check` прошли успешно.
