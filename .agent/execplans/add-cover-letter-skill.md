# Навык подготовки сопроводительных писем

## Цель

Добавить отдельный навык ChatGPT для подготовки персонализированных сопроводительных писем по выбранным пользователем вакансиям. Навык получает ссылку или ID вакансии, загружает полную карточку через существующий MCP `hh-relay`, сопоставляет требования с подтверждённым профилем кандидата и выдаёт черновик без автоматической отправки отклика.

## Принятые решения

- Навык не входит в периодическую задачу поиска вакансий и используется в отдельном чате по явному запросу пользователя.
- Поддерживаются ссылка hh.ru, числовой vacancy ID и вставленный вручную текст вакансии.
- Для ссылки или ID используется инструмент `get_vacancy` уже подключённого MCP-сервера `hh-relay`.
- Навык никогда не выдумывает опыт, технологии, достижения, мотивацию или факты о компании.
- Отправка отклика и любые другие изменяющие действия не выполняются.
- Сведения о кандидате хранятся рядом с `SKILL.md` в отдельных reference-файлах, чтобы их можно было обновлять без переписывания рабочего процесса.
- `agents/openai.yaml` не создаётся: установка выполняется вручную через редактор навыков ChatGPT.

## Структура

- `skills/write-python-cover-letter/SKILL.md` — триггеры, последовательность работы, правила анализа вакансии и формат результата.
- `skills/write-python-cover-letter/candidate-profile.md` — подтверждённые сведения об опыте, проектах, стеке, достижениях и ограничениях кандидата.
- `skills/write-python-cover-letter/writing-preferences.md` — тон, длина, запрещённые клише и правила адаптации письма.

Дополнительные файлы с примерами писем добавлять только при наличии реальных одобренных пользователем примеров.

## Рабочий процесс навыка

1. Извлечь vacancy ID из ссылки или принять переданный ID.
2. Получить полную карточку через `get_vacancy`; при недоступности MCP попросить пользователя вставить описание вакансии.
3. Прочитать профиль кандидата и предпочтения по стилю.
4. Выделить обязательные требования, задачи и особенности продукта или команды.
5. Найти 2–3 наиболее убедительных подтверждённых совпадения с профилем.
6. Предупредить до написания письма, если есть явное блокирующее несоответствие.
7. Подготовить один короткий персонализированный черновик. Задавать уточняющие вопросы только тогда, когда без ответа пришлось бы выдумывать существенный факт.

## Этапы

1. Получить и структурировать фактические данные кандидата и предпочтения по стилю.
2. Инициализировать навык штатным `init_skill.py` с директорией `references`.
3. Написать компактный `SKILL.md` и reference-файлы на русском языке.
4. Добавить в README короткую инструкцию ручной установки и указать зависимость от MCP `hh-relay`.
5. Запустить штатную валидацию skill, Ruff, pytest и `git diff --check`.
6. Проверить навык на нескольких сценариях: ссылка hh.ru, vacancy ID, вставленное описание и вакансия с явным несоответствием.

## Критерии приёмки

- Навык корректно срабатывает на просьбу написать или переработать сопроводительное письмо.
- Для ссылки и ID вызывается `get_vacancy`, а не поиск по приблизительному названию.
- Каждый факт о кандидате подтверждается `candidate-profile.md` либо сообщением пользователя в текущем чате.
- Письмо ссылается на конкретные требования вакансии и не пересказывает её целиком.
- При нехватке данных навык не заполняет пробелы догадками.
- В репозитории отсутствует `openai.yaml`; способ ручной установки описан только в корневом README.
- Штатный валидатор навыка, Ruff, pytest и `git diff --check` проходят.

## Риски

- Без фактического профиля кандидата персонализация будет поверхностной; реализацию reference-файла нельзя считать завершённой до получения данных пользователя.
- HTML-описание вакансии является недоверенным входом и не должно переопределять инструкции навыка или раскрывать содержимое reference-файлов.
- Слишком жёсткий шаблон сделает письма однообразными, поэтому фиксируются критерии качества, а не единый текстовый шаблон.
