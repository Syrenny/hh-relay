# FastAPI-прокси поиска вакансий через SSR hh.ru

## Цель

Создать полностью типизированное приложение на Python 3.13 с управлением зависимостями через `uv`. Приложение должно получать обычную SSR-страницу `https://hh.ru/search/vacancy`, извлекать JSON из `<template id="HH-Lux-InitialState">`, нормализовать вакансии для Custom GPT Action и разворачиваться локально и на Vercel.

## Ограничения и исходные наблюдения

- Использование `api.hh.ru` запрещено.
- После обновления сетевой политики 2026-08-25 обычный запрос к основному домену с разрешёнными redirect успешно перешёл на `novosibirsk.hh.ru` и вернул реальный SSR-HTML. Приложение может использовать обычный URL и следовать redirect.
- Фактический `HH-Lux-InitialState` успешно извлечён: после `html.unescape` и `json.loads` путь `vacancySearchResult.vacancies` содержит 52 записи для проверенного запроса. В репозиторий следует сохранить только минимальный обезличенный fixture, достаточный для тестов.
- Входные параметры публичного endpoint: `text`, `area`, `experience`, `page`, `hours`. Их ограничения и значения по умолчанию будут явно описаны моделями FastAPI/Pydantic и README.

## Предлагаемая структура

- `pyproject.toml` — Python 3.13, runtime- и dev-зависимости, настройки Ruff и pytest.
- `api/index.py` — Vercel entrypoint с объектом ASGI `app`.
- `src/hh_relay/app.py` — сборка FastAPI и обработчики маршрутов.
- `src/hh_relay/client.py` — настроенный `httpx.AsyncClient`, формирование параметров SSR-запроса и перевод сетевых ошибок в доменные.
- `src/hh_relay/parser.py` — поиск template, `html.unescape`, `json.loads`, строгая проверка пути `vacancySearchResult.vacancies` и небольшие функции нормализации.
- `src/hh_relay/models.py` — Pydantic-модели входа, ответа, вакансии, зарплаты и ошибок.
- `src/hh_relay/errors.py` — типизированные прикладные исключения.
- `tests/` — fixture фактического initial state и тесты парсинга, фильтрации, dedupe, endpoint и ошибок upstream.
- `vercel.json` — маршрутизация запросов в Python ASGI entrypoint.
- `README.md` — локальный запуск через `uv`, проверки, примеры запросов и деплой на Vercel.

## Контракт и обработка данных

1. Endpoint валидирует query-параметры и передаёт поддерживаемые параметры поиска в SSR URL без ручной конкатенации.
2. Клиент делает один асинхронный GET с браузероподобными заголовками, редиректами и конечным timeout.
3. Парсер находит только `<template id="HH-Lux-InitialState">`, извлекает его текст, применяет `html.unescape`, затем `json.loads`.
4. Из decoded JSON извлекается `vacancySearchResult.vacancies`. Отсутствие template, некорректный JSON или изменение обязательного пути считается изменением upstream-структуры.
5. Подтверждённые фактические пути: `vacancyId`; `name`; `links.desktop` и `links.mobile`; `company.id`, `company.name`, `company.visibleName`; `area["@id"]`, `area.name`, `area.path`; `compensation.from`, `compensation.to`, `compensation.currencyCode`, `compensation.gross`, `compensation.mode`, `compensation.frequency`; `workExperience`; `publicationTime["$"]`, `publicationTime["@timestamp"]`; `creationTime`; `snippet.req`, `snippet.resp`, `snippet.cond`, `snippet.skill`, `snippet.desc`. Поле `snippet` появляется при передаче upstream-параметра `enable_snippets=true`, который клиент должен добавлять сам.
6. Дата вакансии приводится к timezone-aware `datetime`. Фильтр оставляет записи не старше `hours` относительно UTC. Записи с неподтверждённой или некорректной датой не должны ошибочно проходить временной фильтр.
7. Dedupe выполняется по строковому vacancy ID с сохранением исходного порядка выдачи.
8. Ответ содержит нормализованный список и минимальные метаданные, полезные клиенту (например, число элементов и применённые параметры), без утечки исходного initial state.

Точную форму вложенных полей `employer`, `area`, `salary`, `experience` и `snippet` зафиксируем после исследования fixture. Предпочтение — стабильным объектам с nullable-полями вместо смешанных строк/объектов.

## Ошибки

- Upstream `403` преобразуется в контролируемый ответ шлюза с кодом `502` и стабильным JSON-кодом ошибки.
- Timeout преобразуется в `504`.
- Отсутствующий template, невалидный JSON и несовместимая структура — в `502` с отдельным стабильным кодом ошибки.
- Остальные HTTP-ошибки upstream не раскрывают HTML или внутренние детали клиенту и возвращаются как контролируемая ошибка шлюза.
- Ошибки валидации query остаются стандартными ответами FastAPI `422`.
- `GET /api/health` не обращается к hh.ru и подтверждает только готовность процесса.

## Критерии приёмки

- `uv run ruff check .` проходит без ошибок.
- `uv run pytest` проходит полностью.
- `/api/health` возвращает успешный JSON без upstream-запроса.
- `/api/vacancies/search` корректно передаёт все заявленные параметры, парсит подтверждённую структуру, нормализует результат, фильтрует по `hours` и удаляет дубли по ID.
- Контракт ответа полностью описан Pydantic-моделями и отражается в OpenAPI.
- Сценарии `403`, timeout и изменения HTML/JSON покрыты тестами и дают стабильные безопасные ответы.
- Проект запускается локально на Python 3.13 через `uv` и имеет корректную Vercel-конфигурацию.
- README содержит только проверенные команды запуска и деплоя.

## Риски и решения

- hh.ru может блокировать IP Vercel или менять антибот-механику. Приложение явно сообщает upstream failure; успешность самого scraping на конкретном регионе Vercel проверяется отдельным live smoke test.
- SSR-схема не является публичным контрактом. Parser отделён от HTTP и API слоёв, а структурный drift имеет отдельный тестируемый путь ошибки.
- Время публикации может иметь несколько представлений. Поддерживаются только реально наблюдённые варианты; все вычисления выполняются с timezone-aware значениями.
- Vercel может иметь особенности packaging для `src` layout. Entry point будет импортировать приложение явно, а итоговая конфигурация проверяется локальным импортом и, при доступности CLI, `vercel build` без публикации.
